Who owns the books?

Standalone mode starts one mex-engine-N thread per configured engine. Each thread creates its books on startup, tries to pin to its configured CPU, and busy-polls its command ring. One engine can own several symbols. Each symbol has one owner. Separate engines can match concurrently.

In replicated mode, each process has three workers and a main thread. The main thread creates the state machine and replays committed storage during server setup. mex-replica then applies committed entries to all local engines in log and batch order. Engine core settings do not apply in this mode.

How does an SPSC ring hand off data?

Each bounded ring has one producer and one consumer. The producer copies a command or report into a slot and publishes the tail with a release store. The consumer acquires the tail before it reads new slots and publishes the head after reading. The producer acquires the head before it reuses slots when the ring looks full. Each index has its own cache line.

Each configured engine has a command ring and a report ring in both modes. In replicated mode the bridge polls the command rings in turn, and the replica thread writes to the report rings. The animation follows Engine 0 and shows four example slots. Steps show order, with no measured timing.

What does the gateway own?

mex-gateway owns the client sockets, connection and session tables, frame parsing, routing, and socket writes. Both I/O boxes show the same thread. Each loop polls for client I/O, drains up to one ring capacity of reports per engine, then flushes pending writes. epoll polls with zero timeout. io_uring uses the gateway as its single userspace issuer. A short-lived helper creates the ring at startup.

What does commit guarantee?

Every replica applies the same committed log. A batch reply to the bridge contains the count of applied entries. Each replica produces its own client reports and sends them to sessions connected there. A slow socket can be closed if the send buffer fills. Reports can be lost after a disconnect. Replay changes the books. A replica emits reports only for operations after its startup replay point whose timestamps are at or after its process start.
